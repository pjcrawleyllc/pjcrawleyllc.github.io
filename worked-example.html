The part measures its own error

At 12 bits with a 3 % unit-capacitor sigma, the top capacitor's error is about 1.4 LSB rms. A part like that misses a half-LSB linearity spec badly, and no amount of digital cleverness recovers the missing charge. The array itself has to be trimmed.

The calibration needs no external reference and no tester. For a binary-weighted array the ideal condition at every bit is that the capacitor equals the sum of all the lower capacitors plus the terminator, and the amount by which that fails is the linearity step at that transition. So the converter measures its own error with its own comparator, and trims until the residue is nulled.

Result on the default part, with six capacitors trimmed: peak DNL 1.435 to 0.112 LSB. FAIL to PASS.

MEASURED python sar_adc_trim_demo.py --trim-caps 6. The script's own default trims three capacitors, which nulls the three trimmed transitions and leaves the peak at an untrimmed one; six is where the whole part passes.

A routine that completes, reports sensible codes, and makes the part worse

Adding trim capacitance moves a threshold. Which direction depends on wiring and on the sign convention in the trim control logic. If those two disagree, calibration drives every code the wrong way, and it completes normally, reports plausible trim codes, and hands you a worse part than you started with.

So the routine does not assume the polarity. It applies a known trim step, measures which direction reduces the residue, and takes the answer from the measurement.

Half the transfer function wrong, and no plot would show it

The offset and gain correction is fixed-point arithmetic in SystemVerilog. It is specified by a model, so the model is the oracle: every input code goes through both, and they must agree exactly.

  • 20,480 comparisons across five operating points, 4,096 codes each, the entire input space.
  • Bit-exact on every one.

Then the negative control. Switch the RTL to truncate where the model rounds:

  • 2,005 of 4,096 codes disagree. Every error is exactly one LSB.

Half the transfer function is wrong. The maximum error is a single count. Nothing about it would look wrong on any plot you would normally draw. This is the failure the practice exists to catch, and an exhaustive comparison that takes a second to run catches it.

MEASURED check_rtl.py against adc_offset_gain_corr.sv, exit code 1 on any mismatch.

MATLAB or Python, your choice

The golden model ships as both a Python function and a MATLAB function, verified arithmetically identical over the full input space.

If your team has MATLAB, MATLAB is the target: your scripts, your conventions, your plots. If you would rather the flow needed no seat, Python is the target. Mixed teams are normal and fine.

One honest note for teams weighing Octave as a free substitute: base scripting and plotting port with modest effort, but Simulink and Fixed-Point Designer have no Octave equivalent, so anything built on fi() objects or a .slx model does not travel. Better to know that now than in week two.
