What open-weight models get wrong on analog and mixed-signal work, measured.

A design team considering an on-premises model wants one question answered: on our work, how often is it wrong, and how would we know. Published coding benchmarks do not answer it. They measure code that runs and is checked by tests, where a wrong answer throws an exception and announces itself. The published analog benchmarks score circuit questions and designs, and their results are in the second table below, with where we stand on repeating them. The failure that costs an analog team time is a different case, where nothing errors at all and a plausible wrong number goes downstream, and we found no benchmark that counts it separately.

So we built a harness that measures that case specifically, on analog and mixed-signal material, and we published its mistakes along with its results. The models we measured are not named on this page, and the section near the end says why. The published results keep the names their papers gave them.

Models change every few months and these numbers change with them. Keeping a team current on them is part of full support, the $2,500 monthly retainer, described after the second table.

Where this harness differs from the published benchmarks

The coding benchmarks (HumanEval, MBPP and MultiPL-E, SWE-bench, and VerilogEval, RTLLM and CVDP for digital RTL) score code that runs against tests, where a wrong answer throws an error and announces itself. This harness counts the reply that is well formed and wrong apart from the reply that cannot be read, because the first one goes downstream unnoticed.

Most benchmarks give an abstention no more credit than a wrong answer, so guessing pays. AbstentionBench and AA-Omniscience address that on general questions and recall. We found no abstention test built on datasheets, tool release notes or simulator output, so each question here has a twin with the one necessary fact removed.

For digital place and route, EDA Corpus pairs prompts with OpenROAD scripts and iScript-Bench scores Tcl written for a commercial tool. We found no public benchmark that scores Verilog-AMS, VHDL-AMS, SKILL, OCEAN or Spectre work, or the reduction of measured converter data.

Reproducibility and the cost to deploy are seldom part of a published score. Here eight of thirteen rows changed at least one answer between identical runs, reported row by row, and the hardware and break-even are priced further down.

The four tests, and a real question from each

Twenty-six tasks in two families, graded by code with no human judgement in the loop. Every question below is the real one, as the model received it. Ground truth for the data reduction family is a published converter model, exact by construction, with tolerances derived from the printed precision of the inputs and propagated through each definition.

1. Reading a datasheet

Can it pull the right fact out of supplied material and return it in the exact shape a program downstream can read. When it fails, it is usually the envelope that is wrong and seldom the fact.

QUESTION: What is the name of pin 7? Answer with the pin name. UNIT FOR THE ANSWER: label MATERIAL: pin name type 1 VIN+ analog in 2 VIN- analog in 3 GND supply 4 VS supply 5 REF analog in 6 OUT analog out 7 SHDN digital in

The reply must be one JSON object with three fields: the answer, a boolean saying whether the material can settle it, and a one-sentence reason. Eight of the ten open-weight rows scored 96 to 100 percent here. The two that did not, rows J and K at 72 and 56 percent, mostly failed the contract rather than the question. Row K misspelled one field name on 26 of its 60 replies across this test and the next. Its answers were largely right. Read as intended, by the same grader, that one field moves it from 33 right of 60 to 54. One character cost it the bottom of the table.

2. Knowing when to abstain

Each of the ten questions above has a twin of the same form and length with the one necessary fact removed. The generator writes each material both ways, so the correct abstention is known before any model sees the task. A model that answers the twin anyway is confidently wrong, and that is the only failure on this page with a hard exclusion gate.

QUESTION: According to these release notes alone, was the command 'Export /csv' added in SIMX 8.4? Answer with the string 'yes' if the notes list it; if the notes do not settle the question, set not_evaluable. UNIT FOR THE ANSWER: label MATERIAL: SIMX 8.4 release notes - script commands added in this release Show /plain /file <path> write a tabulated result to a file Netlist /raw emit the flat netlist SetPrecision <digits> printed precision for Show

A list that may be partial does not settle whether something is absent, so the right answer is an abstention. The gate, written before the runs: a row answering more than one tenth of its unanswerable questions is excluded whatever else it scores. The worst row managed 2 of 30, which is 0.067. We wrote this gate expecting it to exclude somebody, it excluded nobody, and we are reporting that. The abstain column in the table is stricter than the gate, because it counts every reply to a twin and a reply that could not be read counts against it. Row K's 60 percent is ten unreadable replies and two confident answers in thirty.

3. Computing in the reply

The data is in the question and the answer comes straight back as numbers. The trap is a definition whose wrong-but-valid twin sits one line away. An endpoint integral non-linearity is a real quantity, and giving it where best-fit was asked is a silent wrong answer.

Definitions (use exactly these): LSB = Vref / 2^N; thresholds th[0..2^N-2] ascending for Vref = 1.2 V. Best-fit line: ordinary least squares of th[j] against j over ALL thresholds j = 0..2^N-2. inl_bf[j] = (th[j] - (slope*j + intercept)) / LSB for every j. peak_inl_bestfit = max |inl_bf[j]|; slope_LSB_per_code = slope / LSB. TASK: Reply with exactly one JSON object, no prose, no code fence, with these numeric fields: peak_inl_bestfit_LSB, slope_LSB_per_code. DATA (CSV, 63 rows, N = 6 bits): index,threshold_V 0,0.018037529 1,0.035987874 ... 61 more rows

The open-weight rows work the 63-step array through in their reasoning channel, so this test ran at eight times the first run's reply limit. At that budget 17 of the 30 trials came back right, five came back silently wrong and eight were cut off. Those are the figures in the table. This is the mode to avoid in production.

4. Writing a script

The same three questions, over a 4,095-row file the message only samples. The reply is a Python script, which the harness runs in a fresh folder with a timeout, and its printed output is graded exactly as the numbers above are.

Definitions (use exactly these): LSB = Vref / 2^N (not Vref / (2^N - 1)). dnl[0] = th[0]/LSB - 1; dnl[k] = (th[k] - th[k-1])/LSB - 1; dnl[2^N-1] = (Vref - th[2^N-2])/LSB - 1. The two end codes are bounded by the rails, not by two thresholds: peak and rms are taken over the interior codes 1..2^N-2 only. TASK: Reply with exactly one Python 3 script in a fenced block and nothing else. It reads the CSV at sys.argv[1] and prints one JSON object with these numeric fields: peak_dnl_LSB, rms_dnl_LSB, peak_inl_LSB, dnl_at_msb_LSB. Standard library and numpy only; no file writes; no network. The CSV has 4095 data rows for an N = 12-bit array.

Nine of the ten open-weight rows scored 89 to 100 percent here, on harder data than test 3, at the same reply budget that defeated every one of them in test 3. Nothing about the model changed between the two. What changed was whether something else was allowed to do the arithmetic.

How a reply is scored

Every reply lands in one of five classes, and each is counted apart because each costs something different.

  • Right is the correct answer inside a derived tolerance, in the form asked for, or a correct abstention on a question the material cannot settle.
  • Silently wrong is well formed and wrong. It parses, it fills the template, and the number is wrong. This is the one that costs real time, because nothing downstream says so.
  • Unreadable is malformed, so something says so: no object in the reply, a missing contract field, a script that stops with an error. It costs time, and a program reading it fails visibly, so nobody is misled.
  • Confidently wrong is an answer to a question the material cannot answer. It is the worst case and the only one with a hard exclusion gate.
  • Nothing to grade is a reply that came back empty, was cut off at the length limit or filtered by the provider, or a request that failed after its retries. It is never scored as right or wrong, and it has its own column.

What we have not tested

Stating this plainly is part of the method.

Every number on this page came from models running on somebody else's hardware, reached through an aggregator. That screens candidates and it is not deployment evidence, because the serving stack, the quantisation loaded and the batching are all the provider's. Nothing here has run on a card in this office.

Eight of thirteen rows changed at least one answer between identical runs at temperature zero with a seed set, on pinned endpoints, and four more could not be compared because a probe came back empty. Our own comparison rule once counted a capital letter and a multiplication sign as changes. It was corrected, and under the corrected rule the count is still eight. The changes look like real nondeterminism in serving, concentrated on borderline questions where the model is deciding whether to answer at all. The re-run those rows are owed has not happened yet, so the figures from the second run are one sample per cell on rows shown not to repeat.

No open-weight model has yet been asked to drive a simulator. We have the controls built for it: a pair of circuits where the same checker returns opposite verdicts, and on the faulty one the simulator's own records and the circuit geometry agree with each other perfectly and both describe the wrong circuit, with no error reported anywhere in the tool. Only comparison against stated intent caught it. That control reproduced a week later on a rebuilt circuit with identical figures. What has not happened is a model producing the build commands, and that is the next measurement.

The code-writing family, where the finding above suggests these models are strongest, is built and has no measurement at all.

The differences between the arms are the measured value of each, which is the part of a deployment that can be bought and the number a prospective client cares about. This is the first measurement on the work the site is about, which is driving a tool to a design rather than answering questions about one.

AnalogCoder on this year's models. The fifteen transistor-level tasks with the paper's settings, so the second table gets a 2026 figure beside each 2024 one.

The compute-in-the-reply test, rebuilt so a cut reply still yields something to grade. A shorter array, the first intermediate values in the reply so the definition can be graded before the arithmetic finishes, and one continuation when a reply is cut. This can lower the accuracy figures above and cannot raise them, because trials that return nothing today will come back right or wrong.

How the measurement is kept honest

The parts of the method that matter more than any individual score.

Predictions are written into a file and hashed before the first trial of a campaign, then scored mechanically in the result. Nineteen such predictions were scored across the two campaigns. Twelve held, four failed and three could not be evaluated. We publish the failures, because a prediction written after the run is a rationalisation.

Rosters that have run are never edited, because their hash sits in a pre-registration.

The harness checks itself before each campaign, and a campaign refuses to start unless that self-test passes and the harness version matches what the test kit expects. Older harness versions are kept, because the test suite uses them as negative controls: a control that reproduces the fix is not a control.

A grader change is tested by mutation. We deliberately break the grader and confirm it then fails exactly the cases it should.

Our own defects are numbered, published, and reported with the mechanism that caught each one. The count passed forty on the harness alone. Several reached the engineer before being caught, including a passing test suite that crashed its own runner, a manifest that omitted its own failures, and twice a result true of one folder stated as a fact about the machine. The verification discipline surfaced those and a person judged them. We think that record is worth more to a prospective client than a page of clean results would be.

The same discipline produced the evidence cases: predictions hashed before the run, mechanical scoring, defects published with the mechanism that caught each.

Why the models are not named

Two reasons, and one limitation.

A named league table dates fast. These releases turn over in weeks, and a page that ranks ten of them by name is wrong within a quarter and invites an argument with whichever vendor came last. What does not date is the structural finding: that giving a model a sandbox mattered more than which model it was, that nobody failed the abstention gate, and that bandwidth rather than memory sets the card count for a dense model writing long answers.

The second reason is that a single misspelled field name moved one model from mid-table to last. Publishing that against a name would be a claim about a product. Publishing it against a label is a claim about output contracts, which is the useful version and the one that will still be true next year.

The published results in the second table keep the names their papers used. Those are citations of someone else's figures, and the names are how a reader checks them. Our remeasurements beside them name their models too, because each one repeats a paper's comparison on the paper's own models and a later release of the same family, and that comparison needs the names.

The limitation: the parameter counts and deployment classes are kept because the hardware argument cannot be made without them, and anyone who follows open-weight releases could narrow several of these rows down from those columns alone. The labels remove the vendor framing rather than making the rows unidentifiable. The named version of every table exists, and we will walk a serious prospect through it.

On this material, the sandbox mattered more than the model.

If you are choosing a model to put on site, the measurements above are the ones to ask for, and the ones to ask any vendor for. The named version of every table exists for a scoping conversation.
